## U1：字段自然高度，工作面有界滚动

**场景**：抽屉含短表单，也有另一种入口承载长列表；多个同域入口共用通用外壳。

**Bad**：给表单网格 `flex-1` 后让自动行平分剩余高度；为修一个贴边抽屉，给通用外壳全局增加 padding；只看列表截图和横向溢出。

**Good**：外壳负责有界高度、标题/底栏与正文滚动；表单字段自然高度、顶部排列，剩余空间留在字段之后。长列表或编辑器独立填充工作面并允许收缩；领域留白通过同域正文组合维护，逐项盘点其所有入口。

**边界与验证**：填满表格不意味着拉伸字段；浮层、页面和复杂工作区可有不同合同。真实浏览器覆盖短窗口、多行字段、长列表与窄容器，测量标签到控件距离、滚动归属、标题与底部动作可达性。静态入口清单不能证明这些几何成立。

<a id="u2"></a>

## U2：点击区域正确不等于文字布局正确

**场景**：横向导航支持不同语言和可变长度标签，旁边还有账户/主题等工具；按钮包含文字与图标。

**Bad**：所有导航项固定宽度并允许压缩，看到 `gap` 正确就验收；按钮图标和文字分别放在两条布局轨道，认为 `justify-center` 已保证整体居中。

**Good**：导航点击区域随内容扩展，组内与组间节奏使用项目 token；空间不足时遵循已确认的导航结构调整。按钮文字与图标作为同一内容组对齐；长文本有明确处理且核心入口仍可发现。

**边界与验证**：不复制 MaaS 的 padding、按钮形状或移动断点。等待实际字体加载，分别测点击区、文字、图标边界；覆盖最长支持语言、临界容器、hover/focus/active 和真实路由点击，确认文字不重叠、内容中心合理且工具组可达。

<a id="u3"></a>

## U3：浮层结束后页面恢复可交互

**场景**：操作菜单打开编辑抽屉，抽屉内又可打开确认弹窗。

**Bad**：只测每个浮层单独关闭；整页不能点击时用全局 `body.style.pointerEvents = ""` 补丁。根因是多个浮层运行时分别记录/恢复全局锁时，补丁会破坏模态合同。

**Good**：按实际依赖解析与打开/关闭时序定位锁所有者，保证适用的共享运行时与清理机制一致；正确继承 Portal 主题，逐层关闭并恢复焦点。MaaS 的依赖路径合同是该版本的具体修复证据，不要求所有项目照搬 override。

**边界与验证**：还可能是遮罩、事件或生命周期问题，不能看到症状就断言依赖重复。走完“菜单 → 抽屉 → 内层弹窗 → 关闭/取消/Escape”，重复后确认正常按钮、输入、滚动、焦点及 light/dark surface；无控制台错误不能单独证明恢复成功。

<a id="u4"></a>

## U4：查询条件与权威数据一致

**场景**：资源列表使用远程分页，高级筛选可取消；页面计数又是删除前置判断的重要提示。

**Bad**：关闭筛选浮层就写回半成品；只过滤已加载的一页却展示全量搜索；显示零资源时直接放宽后端删除保护；确认框提交时读取当前选择而不是原目标。

**Good**：明确草稿、已确认条件与已执行查询的关系，按既有即时/显式合同触发请求；取消不改变已应用条件，翻页使用同一查询快照。数量与状态沿真实 API 字段和映射链核对，纠正展示归一化；确认操作固定目标 ID 与范围。

**边界与验证**：完整本地集合可以本地过滤；接口不支持的全文搜索不能由组件虚构。验证确认/取消/重置、真实 payload 与 total、翻页/刷新、snake_case/缺字段等合同允许的输入；列表刷新后目标不变。查询失败、空结果与零值分别断言，不能用样例数据兜底或削弱业务保护。

<a id="u5"></a>

## U5：按已确认任务合同实现原型

**场景**：统一创建入口覆盖多类资源；其中导入需显式确认，复杂规则配置需要可返回的长工作面。

**Bad**：套新侧栏/页签却保留“选文件立即上传”；用万能 URL 表单替掉 ZIP/Git 等类型能力；所有资源都塞进 Drawer；Demo 自建导航，无法回到真实工作台。

**Good**：先核对真实外壳与入口，再按每类资源列出选择、追加/移除、提交、部分失败、重试、编辑和返回合同；统一入口复用外壳，领域表单和 API 各自适配。长流程选择合适页面，短期编辑复用抽屉；按已确认流程保留来源上下文和草稿。

**边界与验证**：文件即传或提交后传由产品合同决定，原型不证明真实后端能力。旧断言须接受已确认新合同审查；逐类走通创建与返回，核对草稿、权限范围、真实请求和结果回读。复用共享控件也要比较容器、密度及具体资源组件，不能只验收相似功能名称。

<a id="u6"></a>

## U6：预览当前草稿，分清发布对象

**场景**：配置编辑器支持只读预览，同时可查看历史版本；保存、发布与生效是不同阶段。

**Bad**：当前表单预览要求先发布；修改输入后仍展示旧结果；历史与草稿共用结果状态；填写发布说明却没有写入真实请求。

**Good**：领域支持的只读预览直接消费当前已校验表单快照，依赖变化后使旧结果失效；草稿与历史可共用展示组件，状态和来源独立。当前工作面只显示相应对象的操作，字段进入实际请求和持久化合同，清楚反馈保存/发布/生效阶段。

**边界与验证**：预览如果调用外部服务或产生副作用，先按真实能力和授权设计，不能假定纯本地。检查未保存修改、输入变化后的失效、历史返回、各写入口相同校验及 payload/回读；预览成功不等于发布成功或运行时生效。

<a id="u7"></a>

## U7：连续输入验收覆盖新增编辑器

**场景**：Schema 参数名可编辑，行可以新增、删除，后续可能加入排序。

**Bad**：行 key 包含 `${item.name}-${index}`；用一次性 `fill` 检查最终值；门禁只覆盖旧标签编辑器，未纳入新 SchemaEditor。每输入首字符就重挂载失焦，同一问题再次出现。

**Good**：行身份与可编辑字段分开，使用贯穿草稿生命周期的稳定 ID；动态编辑器进入适用的行为回归与组件覆盖清单。Pole 当时有限操作下采用索引的修复不作为通用默认，排序或中间增删必须按真实身份验证。

**边界与验证**：稳定 key 不能证明所有失焦原因已消除。逐字符键入完整字符串，同时检查焦点仍在原控件；新增、删除、类型切换、失焦再编辑后重测。静态清单与源码规则补充浏览器行为，各自说明覆盖范围。
