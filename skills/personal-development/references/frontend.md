# 前端编码：TypeScript、React、Tailwind CSS、shadcn/ui

与[通用准则](core.md)一起执行；页面与交互决策同时遵循[企业 UI/UX](enterprise-ui.md)。以下是个人默认，项目现有框架、版本和明确约定优先。

## 技术选择与边界

- 新建且未指定技术栈的企业 Web 前端默认采用 **TypeScript + React + Tailwind CSS + shadcn/ui**。已有项目沿用实际技术栈；本规范不授权迁移、升级或追加一套组件库。
- 编码前核对 `package.json`、锁文件、TypeScript 配置、Tailwind 入口、`components.json` 及已有组件目录。按安装版本使用 API；Tailwind 不同大版本的主题、扫描和插件配置不能混用，shadcn/ui 的组件底层实现以当前项目为准。
- 三层职责同时成立：React 管理业务数据、路由与受控状态；Tailwind 管理 token、布局和视觉变体；项目维护的 shadcn/ui 及其底层原语管理交互、键盘与焦点。按语义选择 Tabs、RadioGroup、Select 等真实控件，不用一组 Button 或 `div` 只模拟外观；核对实际 JSX，导入组件本身不构成采用证据。
- 路由、数据获取、表单、校验与状态管理优先复用已有方案。SSR/RSC 与客户端边界由框架决定，只把交互所需部分放到客户端；不为局部需求默认引入全局 store 或新的请求框架。

## TypeScript 与数据边界

- 新项目默认启用 `strict`；存量项目在任务范围内补类型与检查，不通过一次功能修改擅自迁移全仓。公共 props、领域状态与请求/响应定义清楚；局部变量利用推断。
- 不可信输入先用 `unknown` 接收，在适配边界校验并收窄；`as`、非空断言和 TypeScript 类型本身不能证明服务器数据有效。复用项目已有校验器或生成客户端，不机械建立重复模型。
- 互斥流程用带标记联合表达，区分初次加载、成功空结果、查询失败及领域实际需要的其他状态；刷新旧数据时单独表达新鲜度与错误，不以 `data ?? []` 吞掉失败。
- 标识符、状态码、时间与单位按领域合同处理；显示文本与协议枚举分开。表格时间、数值与文案沿用项目本地化机制，避免跨页面各自格式化。

类型收窄与联合类型参考 [TypeScript 官方文档](https://www.typescriptlang.org/docs/handbook/2/narrowing.html)。

## React 组件、状态与副作用

- 默认函数组件与组合；按业务能力组织页面、数据适配和组件。复用确有相同语义的 Button、Field、列表工具栏和状态反馈；不同业务的数据与动作保留独立适配，避免用大量布尔 props 拼成万能页面。
- 明确状态所有者：可分享或需返回恢复的筛选/分页按路由合同进入 URL；交互与草稿尽量局部持有；服务器状态交给项目数据层。URL 不存凭据，草稿持久化需明确用户、资源和环境边界。
- 渲染保持纯粹；可从 props/state 计算的值直接派生，用户操作在事件处理器执行。Effect 用于同步外部系统，依赖真实且完整；订阅、计时器及请求具有清理或失效机制。参见 [React Effect 指南](https://react.dev/learn/you-might-not-need-an-effect)与 [F1](cases-frontend.md#f1)。
- Hooks 按当前 React API 的规则调用；普通 Hooks 位于组件或自定义 Hook 顶层，不靠关闭 lint 掩盖依赖或调用顺序问题。列表使用稳定业务 ID，避免排序、筛选后索引 key 将编辑状态关联到其他资源。参见 [Hooks 规则](https://react.dev/reference/rules/rules-of-hooks)。
- 请求与缓存键包含实际影响结果的用户/租户、环境、资源和参数；切换上下文时隔离旧数据。快速筛选或导航后，旧响应不能覆盖新页面；使用已有数据层的取消/失效能力，手写请求则验证响应归属与清理。
- 写操作明确待提交、请求中、已受理、业务完成、失败或结果未知中实际存在的阶段；重复点击受控，超时后按合同查询状态。乐观更新仅用于可回滚且语义清楚的操作，失败要恢复并说明。
- 危险行操作在打开确认时固定资源 ID、作用域及适用的 revision，提交始终使用该快照；列表刷新、排序或当前选择变化不能把操作目标换成另一条记录。响应与流式回调同样绑定发起时的资源，不能读取当前选中项决定归属。
- 输入过程中保持组件身份、焦点与草稿稳定；避免组件类型随渲染重建、用输入值作 key 或依赖全局点击补丁维持输入。复杂表单与 Schema 编辑器覆盖连续输入、失焦后再次编辑和嵌套配置，不只验证第一次输入，参见 [U7](cases-enterprise-ui.md#u7)。
- 性能先测量再优化，`memo`、`useMemo`、`useCallback`、虚拟化与拆包按实际瓶颈采用；大表格的优化保留搜索、键盘和可访问性语义。

## 组件选型与内部复用

### 选型顺序

1. 先查项目组件目录、组件展示页与邻近页面，复用已标准化的内部组件，包括项目已引入并调整过的 shadcn/ui；确认其合同和适用范围，避免按截图重新做一套。
2. 项目没有合适组件时，通用控件**优先使用当前版本的 shadcn/ui 组件**，如 Button、Input、Checkbox、Switch、Select、Dialog、Dropdown Menu、Tabs、Tooltip 和 Table；有合适组合示例时优先组合。Tailwind 负责样式，不替代现成控件的交互、键盘与焦点逻辑。参见[官方组件目录](https://ui.shadcn.com/docs/components)。
3. 现有控件缺少业务能力时，先通过 props、variant 或组合扩展；例如用现有选择控件实现环境选择，用 Dialog 与表单组件实现配置编辑。仅改变颜色、间距或外壳无需重写底层控件，也不为每个 shadcn/ui 组件创建无收益的同名包装。
4. 自定义前明确能力缺口及现有方案不适用的原因。拓扑图、终端、代码编辑器等专用交互可以采用合适实现，再通过适配组件统一样式、状态与接口；不为凑齐 shadcn/ui 使用率牺牲任务能力，也不因局部需求自动引入第二套通用 UI 库。

shadcn/ui 提供可修改源码与可组合接口，内部组件应沿着这些接口维护和扩展。参见[官方组合原则](https://ui.shadcn.com/docs)。

### 组件归属与提取边界

沿用项目目录与依赖约定，下表是职责分层，不要求为本次修改迁移目录。

| 层次 | 职责与依赖 | 典型内容 |
| --- | --- | --- |
| 基础 UI | 统一视觉和基础交互，不直接请求业务 API 或读取当前租户/环境 | 项目维护的 shadcn/ui Button、Input、Dialog 等 |
| 共享交互模式 | 组合基础 UI，用数据与回调表达稳定合同，不内置某页路由或后端字段 | Field、EmptyState、列表工具栏、确认操作、搜索选择等 |
| 领域组件 | 封装同一领域的展示与交互，领域适配负责请求、权限和协议转换 | EnvironmentSelect、ServiceStatus、ModelResourceSummary 等 |
| 页面局部组件 | 当前页面特有的编排与布局，随该功能维护 | 单页专用配置区或预览区 |

- 同语义的已存在控件应复用其权威实现；真正共用的变化在共享层维护，页面通过参数或适配表达差异。视觉相似而规则不同的控件可共享外壳，业务规则保持独立。
- 共享外壳与领域内容分开：只有某一页面家族需要的 padding、工具栏或分区结构放到其共享组合，不修改通用 Drawer/Dialog 默认值影响全部调用方。页面不复制基础控件的 active、disabled、pending、focus 样式；稳定差异进入共享 variant。
- 新组件先覆盖当前合同；有真实共用场景或明确的多处需求时再提取稳定部分，不把每个局部片段都放进全局组件库。共享组件不依赖页面私有模块，避免循环依赖。
- 跨页面复用优先使用项目内共享模块；跨应用有明确复用需求时沿用 monorepo package 或内部 registry。包发布、独立组件库、主题迁移须在任务范围内，不由“可复用”自动触发。

### 自定义组件的标准合同

新增或提升为共享组件时，按其能力明确下列合同；简单展示组件只保留适用项。

| 合同 | 标准化要求 |
| --- | --- |
| 公共 API | 使用领域名称及明确类型；沿用项目 `value`/`onValueChange`、`open`/`onOpenChange` 等惯例。受控/非受控模式、默认值与回调触发时机清楚，避免多个布尔开关拼出非法组合。 |
| 视觉 | 复用项目 token、图标来源、variant、size 与密度约定；有限差异用具名变体。`className` 用于合理布局与扩展，反复覆盖基础样式的需求回收到共享变体。 |
| 状态 | 按需定义 disabled、loading、empty、error、selected 等状态及可用动作；加载与禁用区别明确，错误不抹掉有效输入，状态含义与同类控件一致。 |
| 交互与无障碍 | 继承底层语义，明确键盘、焦点、可访问名称与表单关联；保留适用的 `id`、ARIA、事件及 ref 能力。扩展 props 不泄漏到无关 DOM，不覆盖原有处理器导致内部行为失效。 |
| 数据与副作用 | 可复用展示/输入组件通过类型化数据与回调工作；请求、权限和协议转换归属明确。需要内部请求的领域组件以显式依赖或领域数据层组织，避免暗读全局上下文。 |
| 使用与维护 | 靠近实现提供最小使用示例，说明用途、适用范围、关键状态和扩展方式；复用已有 Storybook、展示页或文档，不为小组件强制搭新平台。共享接口调整检查真实调用方。 |

修改共享基础组件前检查已有用法及本地定制；引入或更新上游源码时审查 diff，保留项目扩展，不用 CLI 覆盖后的成功日志替代兼容性判断。新增交互合同或改变共享行为时验证适用状态、键盘/焦点及不同调用方，案例见 [F4](cases-frontend.md#f4)。

## Tailwind CSS 与基础交互

- 颜色、间距、字体、圆角与状态反馈优先复用项目 token 和组件 variant。使用 `bg-background`、`text-foreground` 等已有语义 token，主题调整在统一入口完成；业务页面不逐页重写基础视觉规则。参见 [shadcn/ui 主题](https://ui.shadcn.com/docs/theming)。
- 语义 token 的命名、映射和产物逐层核对，新增变量避免与既有品牌变量同名异义；浅/深主题覆盖文字、占位、禁用、固定列和弹层。Portal 应继承正确的主题上下文，不能只验证页面根节点；SSR 首轮状态与 hydration 一致，浏览器偏好按框架合同恢复。
- Tailwind 状态样式使用包含完整类名的映射，不拼接 `bg-${color}-500`；构建扫描不能理解任意运行时组合。有限变体用类型化映射或项目已有 variant 工具，真正连续的动态值可用 CSS 变量/内联样式。参见 [官方类名扫描说明](https://tailwindcss.com/docs/detecting-classes-in-source-files)与 [F2](cases-frontend.md#f2)。
- 普通布局优先 flex/grid、响应式约束及正确的收缩边界；长名称、URL、代码和表格有局部换行/溢出策略。任意值与自定义 CSS 用于明确需求，不把截图坐标写成整页固定尺寸。
- 修改 Dialog、Popover、Select 等组件时保留其名称、键盘、焦点与关闭合同；组件库不能替应用证明无障碍。用原生 button/link/form 表达动作、导航与提交；图标按钮有可访问名称，字段有持久 label，错误关联字段且状态不只靠颜色表达。
- 浮层验证完整转换路径：菜单打开抽屉、抽屉内弹窗、Escape/取消和重复打开关闭后，页面仍可点击、滚动及聚焦。若组件运行时共享全局点击/滚动锁，检查依赖实例、Portal 与锁释放；不能以全局强制清空 `pointer-events` 或 body 样式掩盖问题。参见 [U3](cases-enterprise-ui.md#u3)。
- 前端权限用于说明可用动作，服务器仍负责授权；受限或禁用状态给出可理解原因。错误正文不泄露凭据、原始堆栈或内部配置，诊断信息按权限放到详情；密钥不进入日志、URL 或默认持久化草稿。

## 验证

按[前端门禁](quality-gates.md#frontend)核对真实命令，再执行[企业 UI 验收](enterprise-ui.md#验收与证据)。不因文案或纯样式小改动新增无收益测试；项目已有必需检查仍需运行。

| 变更 | 需要的证据 |
| --- | --- |
| 类型、纯逻辑或组件合同 | formatter/lint、类型检查及适用行为测试；构建不能默认代替类型检查 |
| 请求、表单或异步状态 | 正常/拒绝/失败、草稿保留、重复提交、快速切换与旧响应；检查实际请求目标和 payload |
| 页面、样式或基础交互 | 真实浏览器检查相关页面族、目标视口/短高度/容器、长内容、键盘与焦点；涉及生产 CSS 时检查 token utility 与 computed style |

[前端案例](cases-frontend.md)为带上下文的教学片段，不是独立应用，也不受 `verify_examples.py` 覆盖。用于项目时补齐依赖并运行该项目类型、构建与行为检查；规范校验通过不等于页面或业务通过。
