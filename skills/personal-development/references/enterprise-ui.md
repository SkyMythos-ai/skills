# 企业软件 UI/UX 与可用性

适用于微服务管理、AI infra、平台控制台等企业应用的页面设计、实现与审查。目标是让目标用户理解当前处境、完成主要任务，并在失败后知道下一步；视觉密度服务于工作效率和上手成本。

## 设计起点与复杂度

1. 从已有项目和需求确认主要用户、最常见任务、使用频率与操作风险；说明页面入口、主要动作、完成反馈和失败恢复。小改动沿用现有任务模型，不强制新增研究或设计文档。
2. 默认路径只要求完成任务所需输入；低频配置、调优项和原始协议放在清楚命名的高级区域。保留可发现入口，并显示已生效的非默认项；费用、权限、数据丢失和生产影响在决定前可见。
3. 新手通过合理默认值、示例、就地解释与可操作空状态开始工作；熟练用户按需求获得搜索、筛选、批量操作、模板或快捷键。自动化与快捷方式仍显示作用范围及执行结果。
4. 采用[渐进披露](https://www.nngroup.com/articles/progressive-disclosure/)组织复杂度。保留目标用户熟悉的领域术语；必要概念就在使用处解释，避免要求用户先理解内部服务拓扑才能完成普通任务。复杂应用仍需支持专业工作流，参见 [NN/g 复杂应用指南](https://www.nngroup.com/articles/complex-application-design/)。

已有产品先核对真实外壳、导航、入口、共享组件及已确认设计。简化入口保留已有能力与深链，原型使用现有产品结构并贯通主流程；恢复既有设计时比较容器、密度、滚动和具体成员/资源组件，不能只换成同一种 Popover 就认为一致。

先确认设备、语言、主题与工作面范围。仅桌面项目仍验证窗口缩放、短高度和 sidecar 容器；移动端、暗色等按项目合同验收，不因通用规范追加范围。营销表面与高密度工作台分别服从所在产品的视觉规则，组件复用不自动授权重组导航或主题。

## 尼尔森十大原则：企业场景检查点

依据 Jakob Nielsen 的[十大可用性启发式原则](https://www.nngroup.com/articles/ten-usability-heuristics/)。下表是面向企业控制台的应用检查点，不是原文逐句翻译。它们用于发现问题；符合清单不能单独证明可用性或无障碍达标。

| 原则 | 本项目中可观察的检查点 |
| --- | --- |
| 1. 系统状态可见 | 发布区分排队、执行与完成；刷新失败时标明数据时间。 |
| 2. 符合用户现实认知 | 文案使用操作者熟悉的“服务”“模型”“环境”，必要缩写就地解释。 |
| 3. 用户控制与自由 | 编辑可退出且按合同保留草稿；取消受理与进程退出分别反馈。 |
| 4. 一致性与标准 | 同类页面的创建、筛选、状态与返回行为一致，并遵循平台习惯。 |
| 5. 预防错误 | 提交前展示目标环境与影响范围；高风险操作采用与风险相称的校验。 |
| 6. 识别优于记忆 | 资源选择展示名称与范围；比较配置时并列显示当前值和待变更值。 |
| 7. 灵活性与效率 | 默认路径易完成；高频用户可用保存筛选、模板或明确范围的批量操作。 |
| 8. 美观与简约 | 首屏突出当前任务所需信息，高级配置有清楚入口。 |
| 9. 帮助识别、诊断与恢复错误 | 区分无权限、校验失败与依赖故障；保留输入并提供相应下一步。 |
| 10. 帮助与文档 | 在字段或失败处提供短说明、有效示例与任务文档入口。 |

## 信息架构与视觉规范

- 导航按用户的对象与任务组织；全局、组织/项目、环境与资源范围清楚。影响查询或写入的当前范围始终可识别，切换后草稿、选择与列表数据按合同处理。
- 页面标题说明当前对象或任务；主要动作有明确视觉优先级，相关次要动作靠近上下文。导航、筛选、操作与状态各有职责，避免重复入口争夺注意力。
- 同类页面共用标题栏与正文基线，加载/空/错误时标题、作用域和必要操作仍稳定可见。非通用的业务动作默认提供简短可见文字，图标和 `aria-label` 补充语义；只在已有明确密度约定或通用动作中使用纯图标。
- 列表用于扫描、比较与处理资源；详情用于解释状态和下一步；监控页突出异常及处置入口。卡片、表格或图表按信息关系选择，不为统一外观把所有数据改为卡片。
- 默认展示能支持当前判断的列和指标；低频详情就地展开或进入详情页。筛选条件、结果数量、分页/排序与批量选中范围可见，明确“本页”或“全部匹配”，刷新与返回行为可预测。
- 有服务端分页时，筛选、排序、页码和每页条数驱动真实查询；不能在首批数据上局部过滤却声称全量搜索。明确查询是即时还是显式应用；显式查询区分输入草稿与已应用条件，翻页/刷新只使用已应用条件，新条件应用后回到首屏。结果计数来自相同查询范围，全局指标需要独立权威数据，参见 [U4](cases-enterprise-ui.md#u4)。
- 复用项目排版、间距、组件和状态色；控件选型与自定义遵循[组件选型与内部复用](frontend.md#组件选型与内部复用)，设计优先基于现有组件与其变体。字号、对比度与留白支持扫描。关键状态配文字或图标，装饰、动画与图表服务于信息，避免视觉效果占用主要任务区域。
- 工作台主体适应可用宽度，长文本阅读区按内容限制行宽。窄屏重排工具栏与布局；宽表格或代码使用局部滚动，主要动作可达。按项目目标视口验证，不机械要求所有表格转卡片。
- 表格、编辑器与短表单采用各自高度合同：数据工作面可填满剩余空间，字段按自然高度顶部排列；逐层确定 flex/grid 收缩和滚动归属，标题与操作不被挤出。不得为填满抽屉而拉伸字段间距，也不能给短表单留下巨型空卡片，参见 [U1](cases-enterprise-ui.md#u1)。
- 导航和控件同时验证点击盒子与文字/图标实际边界；可变语言与长标签随内容扩展，宽度不足时按既定结构调整。CSS `gap`、DOM 不溢出或 `items-center` 不能证明文字间距及视觉居中；字体加载后测量代表控件，参见 [U2](cases-enterprise-ui.md#u2)。
- 成功空数据、筛选无结果、无权限、未配置、加载及失败分别表达。空状态给出有权限且可执行的下一步；技术错误不能伪装成“暂无数据”。
- 轮询与局部失败尽量保持信息区尺寸、可用旧数据和操作位置稳定，同时显示新鲜度与真实状态。骨架只表达等待，不把长期不可用藏成无限加载；已知失败提供可见说明与恢复入口，读屏状态与可视状态保持一致。

## 表单、反馈与恢复

- 字段按用户决策顺序分组，必需项与推荐默认值清楚；单位、格式、继承来源和覆盖效果就地说明。仅在输入影响下一步时逐步展开，避免层层折叠关键选项。
- 交互容器按任务长度选择：短确认用 Dialog，保留列表上下文的轻量编辑可用 Drawer，多分区、联动预览、版本或发布的长流程使用明确的创建/详情工作面。沿用已确认的入口，不用统一组件外观把全部配置塞进浮层，参见 [U5](cases-enterprise-ui.md#u5)。
- 草稿、已保存、已发布与运行生效按领域实际阶段区分；本地预览绑定当前表单快照，支持草稿预览的领域不要求先发布。预览结果与未保存输入分开持有，返回、切换分区与重新预览按合同保留或失效，真实执行前仍按后端合同校验，参见 [U6](cases-enterprise-ui.md#u6)。
- 在合理时机做字段校验，提交后定位并关联错误，保留已填内容。普通成功按影响范围反馈；持续任务使用可再次查看的状态，不仅闪过 toast。
- 点击触发后及时反馈，界面明确哪些动作暂不可用及原因。长任务显示真实阶段或可验证进度；无法测量时说明进行中，不编造百分比或完成承诺。
- 高风险操作展示资源、环境、作用范围和可恢复性，并按风险选择确认、预览或回滚方案；普通可逆操作保持顺畅，不给每次点击增加确认弹窗。后端没有撤销/取消能力时，界面如实表达。
- 错误说明发生了什么、对当前任务的影响和可采取的动作。重试只用于可安全重复的操作；写入超时先处理结果不确定，不能把所有故障统一为“请重试”。
- 交互可用键盘完成，焦点可见且顺序合理；模态对话框有名称、合理初始焦点、焦点约束及关闭后的焦点恢复，关闭策略符合操作合同。复杂控件按其语义实现，参见 [WAI-ARIA Dialog 模式](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)。无障碍标准级别由项目明确，人工交互检查和自动扫描各自留证。

## 验收与证据

按本次风险选择检查，不为每个页面固定生成十大原则报告。

- **任务走查**：从真实入口完成主要任务，能识别当前范围、必要输入、执行结果及下一步；检查本次触达的失败、空状态和恢复路径。新手路径与熟练用户路径均有明确收益，示例见 [F3](cases-frontend.md#f3)。
- **原型对齐**：实现前将已确认原型列为状态/动作合同，覆盖初态、选择与追加/移除、显式提交、部分失败、重试、编辑与返回；同类资源逐类检查，保留各自专属能力。旧测试若固定了被纠正行为，按确认合同调整，不能用旧断言证明新设计，参见 [U5](cases-enterprise-ui.md#u5)。
- **浏览器验证**：真实浏览器检查目标视口、短高度/窄容器与长内容，执行关键点击、连续输入、失焦再编辑、键盘、焦点和返回行为。涉及共享组件或布局时覆盖相关页面族；涉及数据交互时核对请求范围、payload、乱序与草稿保留。
- **视觉与运行时证据**：关键 token 从 production build 验证实际样式，字体加载后检查文字/按钮几何、局部滚动及主题中的 Portal。复现缺陷时回到对应真实路由与状态；最终核对实际浏览器加载的是本次产物，不能把仍运行旧模块的标签页当作回归结果。
- **可用性证据**：设计评审或启发式走查记录“用户任务 → 触发条件 → 问题/影响 → 修复 → 验证”。有目标用户测试或真实使用数据时，评估任务完成、误操作和求助等相关结果；时间、点击数等指标按任务取舍，不设脱离场景的统一分数。
- **交付边界**：静态截图支持视觉判断，类型/lint 支持代码检查，浏览器交互支持执行到的流程；fixture/替身不证明认证、权限或真实写入集成。缺浏览器或真实账号时标明缺口，完成可行检查，不能宣称业务验收通过。
