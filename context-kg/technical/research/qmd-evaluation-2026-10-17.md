# QMD 2.8.3 本地中文检索与增量更新验证

## 结论与范围

用户在向量实验后明确新增约束：不依赖额外模型，复用用户当前模型，允许使用便宜模型。当前建议因此改为 **宿主模型规划与筛选 + 本地无模型全文检索**；不把此前 Qwen embedding 方案作为接入默认。下文向量实验保留为对照事实。QMD 可以只承担全文索引；接入层仍负责 OKF 状态/范围过滤、文档同步保护、来源核验和输出预算。现有渐进导航与无状态脚本保留。本次没有修改 Skill 实现，也没有提交、推送或部署。

研究完成后，用户已授权接入。后续实现的职责、合同与取舍由 [本地全文检索决策](/technical/adr/local-fulltext-retrieval.md) 承载，验证结果见 [任务 Review](/tasks/todo.md)。本页保留研究阶段的实验事实与限制，不把旧实验指标当新实现验收。

### 后续适配层冒烟

新 CLI 在同一真实快照索引 140 篇合法 concept，另 2 篇缺 frontmatter 明确警告并跳过；首次同步约 1.02 s，无变化同步 3 次中位 138 ms。8 问各以新进程执行原问句加此前冻结的最多 3 条规划词，查询前完整 hash 对账，中位 424 ms；输出不超过默认预算。向量行数 0、GGUF 文件 0。

该受限首轮的目标 Hit@5/10 均为 5/8。主 Agent 随后依据原问题，把未命中的 R05/R07/R08 拆为少量独立主题词补查，目标分别在第 10/3/3；这是看到首轮反馈后的工作流冒烟，不是新的盲评。此版没有在脚本里自动发起研究实验的 20 词补召回或模型筛选，不能把此前最终 8/8 移作此版指标。语言理解和进一步筛选由宿主完成，完整 Agent 的准确率、延迟和费用尚未测量。数据见汇总 JSON 的 `implementation_smoke`。

## 复用宿主模型的无向量补充验证

该路线把语言理解放回用户当前 Agent：问题 → 当前模型生成少量关键词/同义表达 → 本地全文多路召回 → 当前模型查看有限元数据、选出少量文档 → 按需读取原文回答。它仍是检索增强生成；不要求 embedding。

- 复用已冻结的 32 个问题。宿主提供的便宜子模型 `gpt-6-luna` 只看问题，不读语料、gold 或旧结果，一次批量产生最多 3 条关键词组合。
- QMD 另建独立配置和索引，三个模型路径故意指向不存在的本地文件；仅调用显式 `lex` 且 `rerank:false`。结束时该索引向量记录 **0**、隔离目录 GGUF 文件 **0**，检索正常完成。没有调用新 provider、读取宿主登录凭据或下载模型。
- 原问题与规划词串做 RRF；通用词项/CJK 二元补召回最多 20 项、权重 0.2，在查看评分前固定。不是为每个 gold 单独调词。仅严格关键词组合时，人工集 Hit@5 为 13/21、真实集 5/8；加入词项补召回后，分别为 **21/21、6/8**，真实集 Hit@10 为 **8/8**。
- 便宜宿主模型第二次只看这 8 个真实问题及每题 10 个候选的 path/title/description/tags/status，不看 gold、正文或评分。按最多 5 条筛选后，真实目标 Hit@1 为 **7/8**，Hit@5 为 **8/8**。这是元数据候选选择，不证明回答正确或当前权威。
- 本地多路全文召回 p50：人工集 **16.9 ms**、真实集 **484.0 ms**；不包括宿主模型规划与筛选的耗时。两次模型调用均为批量试验，未测逐问题延迟、费用或 token，不能声称端到端更快、更便宜或节省某比例 token。候选元数据 JSON 共 28,142 字符/8 问（包含格式），没有正文。
- 词项补召回也使 3 条无答案问题都出现近邻；模型筛选阶段只测了真实正例，未验证无答案拒答。仍需范围、生命周期与证据充分性检查。只做一次盲规划与一次盲筛选，未证明多次模型采样稳定性。

当前聊天模型不是 embedding 模型，不能简单替换向量生成步骤。QMD 2.8.3 的公开 SDK 内部创建具体 `LlamaCpp`，模型配置是 GGUF 模型来源；本次选择绕过其模型路径，直接使用纯全文检索，而非改造其内部 provider。[SDK 构造](https://github.com/tobi/qmd/blob/facd35e01359e59d938bc9418e93fb9318addee3/src/index.ts#L352-L390)

模型步骤应由宿主调度；脚本不复制宿主登录 Token，也不假定登录会话是通用推理 API。宿主支持便宜子模型时按其用户配置选择；不支持时由当前 Agent 完成。独立部署如确实需要远程推理，才显式配置用户自己的 provider/model/凭据，不能静默改用平台凭据。本轮没有实现独立推理调用。

Skill 是围绕工具的工作流，适合让当前模型规划工具参数；不是要求每个脚本自带推理端。[官方 Skills 说明](https://developers.openai.com/plugins/concepts/skills)。若另做独立宿主集成，应使用宿主支持的接口和认证方式；例如 Codex app-server 有其正式的用户授权集成流程，不等于任意本地脚本自动获得调用权。[官方 app-server 说明](https://developers.openai.com/siwc/token-sharing-open-source/codex-app-server)

文档变化只更新本地全文索引，不再有 embedding 构建与补齐窗口；更换聊天模型不要求重建文档向量。QMD 的空文件/根目录等全文更新缺口仍然存在。最终工具应只暴露纯全文搜索入口，避免误调用默认 `query`、`vsearch`、`embed` 而触发额外模型；在该模式下，status 中待 embedding 数量不是全文索引失败。此段实验结束时尚未接入 Skill；后续状态以本页开头链接的实现决策与 Review 为准。

## 可复现边界

- npm 固定 `@tobilu/qmd@2.8.3`，CLI 输出 `2.8.3 (facd35e)`；包的 integrity 记录在本次安装锁文件。源码固定 `facd35e01359e59d938bc9418e93fb9318addee3`。当时 `main` 虽也标 2.8.3，却已有尚未发布的 metadata filter、mtime fast-path 等实现，未算作发布能力。
- 本机 macOS 27.0.1 / Apple M5 Max / 128 GiB / Node 24.18.0；node-llama-cpp 3.20.0。独立模型探针确认 Metal 后端可以加载 Gemma 的 25/25 层；构建日志曾有 Metal source compile warning，未逐次采样每个 CLI 的 offload，以下只声明本机观察耗时。
- 安装、配置、DB、模型及语料均在独立临时目录；Gemma 与 Qwen 用不同 DB 和缓存目录，防止模型混用及目录级 embedding 锁竞争。模型按官方固定 revision 下载，并核对官方 LFS SHA-256。首次完整模型下载遇到 HTTP/2 中断，改用官方同 revision 的分段下载后校验；下载耗时不混入检索/embedding 耗时。
- 人工虚构语料：26 篇中文 concept + 3 篇 index；冻结 24 条原始查询，其中 21 条有明确目标，覆盖两字词、Case ID、中英混合、跨字段、自然语言改写与生命周期干扰，另有 3 条无答案。检索后未按排名调整 gold。
- 真实语料：另一项目 `context-kg` 的只读快照，共 161 篇 Markdown、6,785,864 字节；来源 HEAD 与每文件 SHA-256 已记录。8 条真实查询的 gold 先按元数据选定，随后检查正文支持。它们不是全库唯一相关文档的穷举；抽查发现部分未命中指定 gold 的结果包含实质相关的替代 concept，例如真实 R02 的供应链说明和 R05 的富文本编辑器研究，因此低目标命中不能直接解释为无用或无答案；R06 的目标含历史/存储决策并指向当前 ADR，R02、R08 也有目标/原型与实际验收的边界。
- 原始快照及含真实正文的响应只留本地隔离目录；本仓库只保存汇总，不复制其他项目的知识正文。

## 速度、缓存与构建成本

- 真实快照首次全文索引：1,539 ms；fixture 全文索引：232 ms。
- 新 CLI 进程的词法查询：fixture 中位约 97 ms、真实查询约 110 ms。无变化 `update` 中位约 142 ms（含进程启动，扫描当时 190 篇文件）。它每次仍读全文并 hash，不是 mtime 快速路径。
- 首个无重排向量请求包含模型首次装载：Gemma 约 1.34 秒，Qwen 约 1.49 秒（文件系统已可能预热）；上表中位数不是这个冷进程首次请求。上表语义模式 HTTP 结果来自本地常驻进程，每模式前清空 `llm_cache`；模型在该模式开始前可能已经驻留，每个问题执行三次，分别记录本轮首次与重复耗时。首个向量/重排请求包含对应模型首次装载；样本 p95 和最大值保存在 JSON，不外推稳定尾延迟。两组语义查询都在两组构建结束、DB 缺失/不完整检查通过后运行。
- 默认模型首次 embedding：fixture 3.116 秒，真实快照 288.422 秒；Qwen：fixture 15.806 秒，真实快照 832.024 秒。构建期间存在两组构建/下载并行，不能把这些数值当作隔离的模型吞吐排名。默认 DB 最终 190 个全文 hash、3,730 个 chunks；两组完整性均由 DB 检查，而非仅看 rc=0。
- 普通 `qmd query` 路径（可能自动扩展及重排，具体以运行输出为准）另测 4 个 fixture 问题，每个新进程重复两次：default目标前五命中 4/4，新进程耗时 p50 2.25 秒，范围 1.38–4.36 秒；qwen目标前五命中 4/4，新进程耗时 p50 2.35 秒，范围 1.25–7.44 秒。它与上表显式 typed 查询是不同路径，不把两者混成一个“查询耗时”。
- 片段输出减少的是进入 Agent 上下文的正文量；本次未做 tokenizer 统计和完整 Agent 对照，不能宣称节省了某个百分比 token。

完整模型组合约 2.9 GB，包含两种 embedding、reranker、expansion；这不是仅启用纯词法或单一 embedding 所需的最低下载量。轻量接入可采用显式 `lex`/`vec`、关闭重排，并避免自动扩展。

## 文档变化与监听

独立 mutation 索引验证了以下行为；单 chunk 小文档用于隔离生命周期机制，不据此推算大文档更新成本。

| 场景 | 运行结果 |
| --- | --- |
| 只改文件、不调用 update | 仍查到旧内容；没有原生自动同步 |
| 新增、修改、删除、改名、原子保存 | update 后全文结果与路径更新；删除旧记录 soft-deactivate |
| 同 size 且恢复 mtime 后改写 | 仍能发现新 hash，发布版实际读全文 hash |
| 无变化 update / embed | 索引状态不变；小语料 noop embed 约 0.165 秒 |
| rename 且全文相同 | 可复用既有向量 |
| 修改后 update、尚未 embed | 全文已更新，新 hash 暂时缺席语义候选；embed 后恢复 |
| 删除后 | 删除路径不再返回，孤儿向量仍保留，清理需单独安排 |
| 清空成 0 字节 | **旧正文及 active=1 仍被保留，可查到旧内容** |
| collection 根目录暂时不存在 | **update 返回 0，却把整个 collection 软停用**；恢复目录后再次 update 能恢复 |

另补 1 篇中文正文和中文文件名的单 chunk 探针，11 项观测完成：新增、互斥主题改写、中文改名和删除的全文/hash/向量资格符合预期；URI 保留中文并带命名 index 参数，按 URI 结构解析。该探针不证明大库中文排名质量。

外部 `watchfiles` 单次原型观察：保存→检测约 32 ms，保存→串行 update 并可检索约 515 ms。它不是 QMD 原生 watch，不证明长期事件可靠性、重启恢复或并发安全。未做进程 kill/系统重启恢复试验。

接入时需要把事件当成“待对账路径”提示：启动对账、事件合并、维护后主动刷新、定期补查；根目录/扫描失败必须与删除区分，空文件应明确清除旧索引，查询前核验返回源文件版本。不能承诺多文件同一时刻的原子快照。

发布版的增量以**整篇全文 hash**为单位，元数据/正文变化得到此前未嵌入的新全文 hash 时，会重算该文档所有 chunks；恢复已嵌入的旧全文 hash 可复用；未变 chunk 没有独立 hash 复用。本结论是源码推导，未改动多 MB 文件重跑构建。[全文 hash](https://github.com/tobi/qmd/blob/facd35e01359e59d938bc9418e93fb9318addee3/src/store.ts#L2860-L2863)、[待处理与整篇切分](https://github.com/tobi/qmd/blob/facd35e01359e59d938bc9418e93fb9318addee3/src/store.ts#L1885-L1905)

CLI embedding 锁按 DB 所在目录共享；忙时输出 skipping 却返回 0。已实测遭遇并用实际向量 hash/chunk 完整性识别，等待耗时单列。不同工作树/模型应隔离缓存目录，更新由单写队列管理；DB WAL 不等于整轮 update/embed 崩溃原子性。

## 原向量路线的接入研究（对照，不再作为当前默认）

1. 保留现有“分层 index → 元数据候选 → 必要正文/来源”的导航、权威与生命周期语义；QMD 提供补充召回。2.8.3 发布版不能直接按 OKF `status/type/scope` 过滤，不能拿 main 文档里的 metadata filter 当成已有能力。
2. 普通领域检索用 collection ignore 排除 log、Session Summary 等过程内容，index 继续作为导航；显式历史查询另走相应范围。不要因模型相似度高就把 deprecated、draft 或尚未生效方案作为当前结论。
3. 关键词/精确 ID 走快速路径；自然语言补召回优先评估本次表现更好的 Qwen 多语种 embedding，使用显式 typed `vec` 或 SDK，再按需混合关键词。不能假定 hybrid 必然优于单向量；本次两者真实目标 Hit@5 相同，而纯向量 Hit@1 更高。发布版 CLI `vsearch` 内部仍会做 query expansion；单设 `--no-rerank` 也不会关闭扩展，需避免意外加载 1.7B 模型。
4. watcher 同步全文索引、后台 debounce embedding；更新未完成时通过全文/原脚本兜底。保护空文件、不可用根目录和 rc=0 skip，记录最后成功对账、待 embedding 数量及错误；失败不伪装为成功空结果。
5. 仅输出有预算的少量片段，附原文路径、行号、状态和来源；返回前回读原文件确认版本。过滤后候选不足要补召回或明确不足，不能只在 top-K 截断后默默过滤。
6. 巨型任务页、高频变化的流水文档不宜默认 embedding。全文索引和向量都是可重建本地缓存，Markdown 与手写 index 仍是知识来源；本次完成的是验证，实际接入尚未实施。
